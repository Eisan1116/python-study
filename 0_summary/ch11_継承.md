# 第11章 継承（継承・オーバーライド・ポリモーフィズム・特殊メソッド・抽象クラス）まとめ

> ★ = 特に重要な項目

## ① 章の目的
すでにあるクラス（親）をもとに、似たクラス（子）を「違う部分だけ書く」ことで効率よく作れるようにすることです。「`super()` で親の処理を再利用すること」と「同じ名前のメソッドでクラスごとに違う動きをさせること（ポリモーフィズム）」が二本柱です。

## ② 重要項目

| 項目 | 書き方 | ポイント |
|---|---|---|
| ★継承 | `class Income(Record):` | 親の属性・メソッドをすべて受け継ぐ。子に書かなければ親のものが使われる |
| ★オーバーライド | 子で親と同じ名前のメソッドを定義 | 子のものが優先される。クラス変数（`kind = "収入"`）も上書きできる |
| ★`super().__init__()` | `super().__init__(date, amount, memo)` | 親の初期化を任せ、子は**追加する属性だけ**を書く |
| `super().メソッド()` | `super().__str__() + " [食費]"` | 親の結果に付け足す形で拡張できる |
| ★`isinstance` | `isinstance(r, Record)` | **子クラスも「親の仲間」と判定**される。`type(r) == Record` では子が弾かれる |
| `issubclass` | `issubclass(Income, Record)` | クラス同士の親子関係を調べる |
| 多段継承 | `A → B → C` | 属性・メソッドは「自分 → 親 → さらに親」の順に探される |
| `__` 付き属性 | `self.__secret` | 名前が `_クラス名__secret` に変わり（名前修飾）、子クラスからも直接触れない |
| ★ポリモーフィズム | `for r in records: r.signed_amount()` | 呼ぶ側は種類を区別しないのに、各クラスの実装が自動で使われる |
| 特殊メソッド | `__str__` / `__lt__` / `__eq__` / `__len__` | `print()`・`sorted()`・`==`・`len()` に自作クラスを対応させる |
| ★抽象クラス | `class Record(ABC):` ＋ `@abstractmethod` | 直接インスタンス化すると `TypeError`。子に「このメソッドを必ず書け」と強制できる |

## ③ 基本コード

```python
# ★継承のテンプレート
from abc import ABC, abstractmethod

class 親クラス名(ABC):
    種類 = "既定値"                       # 子で上書きするクラス変数

    def __init__(self, 親の引数...):
        self.属性 = 親の引数

    @abstractmethod
    def 必須メソッド(self):               # 子で必ず実装させる
        pass

    def __str__(self):
        return f"{self.種類} ..."          # Record.種類 ではなく self.種類

class 子クラス名(親クラス名):
    種類 = "子の値"

    def __init__(self, 親の引数..., 追加の引数):
        super().__init__(親の引数...)     # 親に任せる
        self.追加の属性 = 追加の引数

    def 必須メソッド(self):
        return ...

    def __str__(self):
        return super().__str__() + 追加する文字列
```

```python
# 家計簿（総合診断 ex11_review.py）
class Record(ABC):
    kind = "記録"

    def __init__(self, date, amount, memo):
        self.date = date
        self.amount = amount                    # setterのチェックを通す
        self.memo = memo

    @property
    def amount(self):
        return self._amount

    @amount.setter
    def amount(self, value):
        if value < 0:
            raise ValueError("金額は0以上にしてください")
        self._amount = value

    @abstractmethod
    def signed_amount(self):
        pass

    def __str__(self):
        return f"{self.date} {self.kind} {self.amount:,}円 {self.memo}"

    def __lt__(self, other):                    # sorted() で日付順に
        return self.date < other.date


class Income(Record):
    kind = "収入"                               # __init__ は親のものをそのまま使う

    def signed_amount(self):
        return self.amount


class Expense(Record):
    kind = "支出"

    def __init__(self, date, amount, memo, category):
        super().__init__(date, amount, memo)
        self.category = category

    def signed_amount(self):
        return -self.amount

    def __str__(self):
        return f"{super().__str__()} [{self.category}]"


class Kakeibo:
    def __init__(self):
        self.records = []                       # インスタンスごとのリスト

    def add(self, record):
        if not isinstance(record, Record):
            raise TypeError("Recordのインスタンスのみ追加できます")
        self.records.append(record)

    def __len__(self):
        return len(self.records)

    def balance(self):                          # ★ポリモーフィズム
        total = 0
        for record in self.records:
            total += record.signed_amount()
        return total

    def expenses_by_category(self):             # 第6章の辞書集計
        result = {}
        for record in self.records:
            if isinstance(record, Expense):
                result[record.category] = result.get(record.category, 0) + record.amount
        return result
```

## ④ よくあるミス
1. ★`__init__` を `__init_` と書く → エラーにならずに「別名のメソッド」として定義され、親（`object`）の `__init__` が呼ばれて `TypeError` になります。**前後ともアンダースコア2つ**です。
2. 子の `__init__` で `super().__init__()` を呼び忘れる → 親で作るはずの属性がなく `AttributeError` になります。
3. 親のメソッドの中で `Record.kind` と書く → 常に親の値になり、オーバーライドが効きません。`self.kind` と書きます。
4. 型チェックに `type(x) == Record` を使う → 子クラスのインスタンスが弾かれます。継承を考えるなら `isinstance` です。
5. `ValueError(...)` / `TypeError(...)` と書いただけで `raise` を忘れる → 例外が作られるだけで、何も起きません。
6. 抽象メソッドと子のメソッドで引数をそろえない → 呼ぶ側が困るので、`signed_amount(self)` のように同じ形にします。
7. 中身が `super().__init__()` を呼ぶだけの `__init__` を書く → 不要です。書かなければ親の `__init__` が自動で使われます。
8. リストをクラス変数（`records = []`）にする → 全インスタンスで共有されます（第10章の復習）。`__init__` で `self.records = []` にします。

## ⑤ 前後の章とのつながり
- **第6章から**：`get(キー, 0)` を使ったカテゴリ別集計は、クラスの中でもそのまま使えます。
- **第10章から**：`@property` のカプセル化はそのまま子クラスに受け継がれ、`Income` / `Expense` でも金額チェックが効きます。
- **10月のスクレイピングへ**：`requests` の `Response` や BeautifulSoup の `Tag` も、すべてクラスのインスタンスです。`res.status_code` や `tag.get_text()` は「属性」と「メソッド」の呼び出しだと読めるようになります。
- **ポートフォリオへ**：`Record` を継承すれば「振替」「学習記録」などの新しい種類を、`Kakeibo` 側を書き換えずに追加できます。
